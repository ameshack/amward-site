# Asia Meshack — portfolio site

Personal portfolio for **Asia Meshack, MBA**, a marketing, communications and organizational leader. Audience: recruiters, hiring managers and prospective consulting clients. Live at https://ameshack.github.io/amward-site/ (GitHub Pages, `main` branch, repository root).

Pages: home, four specialties (`/brand/`, `/product-marketing/`, `/communications/` titled "Strategic Communications", `/leadership/`) and `/about/`. Specialty URLs are shared in résumés and applications; never change them.

## How it's built

A static site generated by a small Python script, with no framework or dependencies.

- `src/content.py`: all content. Specialties, projects, proof points, logos, experience, awards and education. Each project is defined once and listed by id on a specialty page.
- `build.py`: the HTML templates and the build. `python3 build.py` writes the published pages to the repo root (`index.html`, `brand/`, …, `assets/`). `python3 build.py --preview` writes a review copy to `dist/preview/`, with owner-review notes visible.
- `src/site.css`, `src/site.js`: shared styles and behavior. These cover the menus, the email reveal, redirects from old single-page anchors such as `#brand`, and opening a project's details from `#project-id`.
- `src/img/`: images. `src/img/logos/` holds the official company logos from Wikimedia Commons.

Edit the sources, run both builds and commit the source together with the regenerated pages. Never hand-edit the generated HTML.

### Project fields (`src/content.py`)

`org`, `program`, `title`, `image` (`layout`: side by default, `wide`, `phone`), `outcome` (a figure and label; an empty figure turns the label into a mandate line), optional `secondary` metric, `challenge`, `role_label` ("My ownership" only where she had final accountability, otherwise "My role"), `role`, `approach` (shown as "Strategic approach"), `details` [(heading, html)], optional `media` cards, `links`, optional `compact`.

Inside detail HTML, write `href="@slug/#anchor"` for links between pages and `src="@img/file.jpg"` for images; the build fills in the paths. Text wrapped in `<!--REVIEW-->…<!--/REVIEW-->` appears only in the preview build.

### Publishing workflow

Work on the `redesign` branch, then fast-forward `main` and push. GitHub Pages redeploys in about a minute. A private Claude preview artifact (https://claude.ai/artifact/4Caqs4aP3G6CxSzhmiPogU) is published from `dist/preview/artifact-home.html`.

When replacing an image, give the new file a **new filename**. Browsers cache images by name, so a changed image under the old name won't show up.

## Design

Warm editorial palette: ivory `#F5F3EE`, deep teal `#233B3B`, sage, stone and white. Headings use Manrope; body text uses Source Sans 3. Light theme only. Keep the look, the navigation and the information architecture unless asked.

- Name: **Asia Meshack** everywhere (header: "Asia Meshack, MBA"). Do not use A.M. Ward.
- Change only what's asked. Don't add headings, sections or copy she didn't request, and use her supplied wording verbatim.
- Never invent results, research findings, launch status or authority. When something is missing, flag it rather than filling it in. Keep the qualifiers:
  - $1.7M is *projected* lifetime value.
  - REUSE SF's +51% is agency-reported *intent*.
  - The San Francisco +88% and +85% are *relative* survey increases.
  - The Delta suitcase covers development and prelaunch work only.

- Public assets only. Before using an image, remove executives' names from internal slides, internal-use markings and third parties' names (such as LinkedIn reactions).
- Her email is never written in plain text; it's assembled in `site.js` when a visitor clicks.
- Primary source for facts: her Master CV in Google Drive (`Asia_Meshack_Master_CV_2026-10-23`), including its "factual safeguards" section.
